## 用户可见变化

在表格的“字段”面板中可新建“累计余额”，并配置：

- 期初余额：手动输入，最多两位小数。
- 收入字段：可选，只能选数字或货币字段。
- 支出字段：可选，只能选数字或货币字段。
- 计算顺序：必选，只能选日期或日期时间字段。

计算规则是：

```text
当前余额 = 期初余额 + 截至当前记录的累计收入 - 累计支出
```

同一时间的记录再按 `id` 升序计算。收入或支出空值按 `0` 处理。缺少排序时间的记录显示空余额，且不影响其他记录。

## 数据与版本语义

- 余额不是 SQLite 业务表实体列，不会被表单、API 或 AI 助手直接写入。
- 列表、单条详情、只读 Viewer、筛选、排序、分页和 CSV/JSON 导出共用同一服务端计算管线。
- 先对全表按固定业务顺序累计，再执行界面筛选、显示排序和分页；界面排序不会改变余额。
- 修改旧流水、补录日期、删除、回收站恢复或整表历史恢复后，都会按当前配置自动重算。
- 整表历史仍只保存原始行数据，不把每次可重算的余额写入版本快照。余额配置本身暂不进入整表数据版本。

## API 变化

`POST /api/tables/:tableName/fields` 可使用 `field_type: "running_balance"` 和 `formula_config`。每张表最多一个累计余额字段。

`GET /api/tables/:tableName/fields` 对该字段返回：

- `virtual: true`
- `read_only: true`
- `formula_config`

累计余额可用于 `filter[balance__gte]` 等筛选。按累计余额排序时使用 `page` / `page_size` 分页；不提供只含 `id` 的游标，避免非唯一计算值导致跳行或重复。

## 性能验收

本地确定性基准，每页 100 行：

| 数据量 | 最慢场景 p95 | 门禁 | 场景 |
|---:|---:|---:|---|
| 10,000 | 35.62 ms | 500 ms | 首页、第二页、物理/余额筛选、余额排序、10k JSON 导出 |
| 50,000 | 57.92 ms | 1,500 ms | 首页、第二页、物理/余额筛选、余额排序 |

本组基准 RSS 约 `123.1 MB`。这是开发机结果，生产 VPS 仍需在上线后做真实数据和资源验收。

生产当前表格数据量较小，没有在用户现有表中新建计算字段做破坏性性能测试。生产资源验收确认服务常驻内存约 `75 MB`，未超过 systemd `350 MB` 上限。
