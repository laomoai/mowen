# 墨问 v2.4.0 数据安全与历史版本升级说明

## 发布状态

- 代码范围：SQLite 原生定时备份、笔记历史版本、整表数据历史与差异恢复。
- OpenAPI 版本：`2.4.0`。
- 生产发布：`/opt/mowen/releases/20260913-table-versions-r2`。
- 数据库迁移：`0033_entity_revisions.sql` 和 `0034_table_revisions.sql`。
- 生产上线时间：2026-09-13；Git 闭环日期：2026-09-14。

## 用户可见变化

### 笔记历史

- 笔记页可查看历史版本和字段差异。
- 可将旧版本恢复为当前内容。恢复前状态会先保存为新版本，因此恢复操作也可撤回。
- 同一操作人对同一笔记的连续正文自动保存，在 60 秒窗口内合并为同一版本，减少无意义的版本增长。

### 整表历史

- 表格历史以“整张表的数据集”为版本对象，入口位于表格工具栏，不在单行详情中呈现。
- 新增、修改、删除、批量新增、AI 助手写入、回收站恢复和整表恢复都进入整表版本链。
- 差异先按记录标记“当前新增 / 当前已删除 / 内容有变化”，再展示字段级前后值。
- 整表恢复会恢复目标时点的全部数据行，并保留恢复前状态作为新版本。
- `base_version` 用于防止用户在查看历史后静默覆盖别人的新修改；发生冲突时返回 `409 VERSION_CONFLICT`。

## 实现方式

- 笔记使用对象前像快照，整表使用受影响行的 `before_rows` / `after_rows` 增量日志。
- 日常修改一行时不会复制整张表；只在查看或恢复旧版本时，从当前数据逆向重建目标整表状态。
- 业务写入、版本记录和行数更新放在同一 SQLite 事务内，避免只改数据但未留版本，或只留版本但数据未更新。
- 历史记录按 `team_id` 隔离，并继承已有表格/笔记读写权限。`scope=groups` 的 API Key 不能查看或恢复授权文件夹之外的历史。

## SQLite 备份

- `mowen-sqlite-backup.timer` 每小时调用一次 SQLite CLI `.backup`，无需停止应用。
- 备份先写入同目录临时文件；文件非空且 `PRAGMA quick_check` 返回 `ok` 后，才原子改名为带 UTC 时间戳的快照，同时写入 SHA-256。
- 当前目标目录是 `/opt/backups/mowen-scheduled/`，不自动删除旧备份。
- 当前未上传 R2，也未自动下载到本地。

## API 变化

- `GET /api/notes/:id/revisions`
- `GET /api/notes/:id/revisions/:revisionId`
- `POST /api/notes/:id/restore-version`
- `GET /api/tables/:tableName/revisions`
- `GET /api/tables/:tableName/revisions/:revisionId`
- `POST /api/tables/:tableName/restore-version`

记录级版本接口保留为内部兼容能力，但 Web 界面的表格历史以整表为准。

## 升级和回滚

1. 升级前使用 SQLite `.backup` 生成一致性备份，并执行 `PRAGMA quick_check`。
2. 发布新应用并执行 `0033`、`0034` 迁移。
3. 检查 `_entity_heads`、`_revisions`、`_table_revision_heads` 和 `_table_revisions` 已创建。
4. 验证服务、SQLite、OpenAPI、备份 timer 和内外网健康检查。

代码回滚可将 `/opt/mowen/current` 指回前一 release 后重启 `mowen.service`。新增迁移只添加系统表，代码回滚时不要破坏性删表。数据库点位回退会覆盖新数据，必须单独确认后才能执行。

## 限制与后续项

- 整表恢复仅包含数据行和单元格值，不包含字段、表结构、视图或图表配置。
- 迁移上线前的历史操作无法倒推；现有表在上线后首次发生数据变更时才开始建立版本链。
- SQLite 备份只包含 `mowen.sqlite`，不包含 `/var/lib/mowen/files/` 附件。
- 本场发布不包含备份轮转、异地副本、自动告警、审计日志和隔离恢复演练。
