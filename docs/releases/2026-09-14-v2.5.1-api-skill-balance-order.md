# 墨问 v2.5.1 API / Skill 与累计余额排序修正

## 修正内容

- `GET /api/tables/:tableName` 保留实体 `columns`，新增完整应用 `fields`，其中包含虚拟计算字段的 `virtual`、`read_only` 和 `formula_config`。
- OpenAPI 升级为 `2.5.1`，补齐页码分页和计算字段 Schema 语义。
- 墨问 Skill / CLI / MCP 可读取完整字段、使用页码/筛选/字段选择，并可创建或更新累计余额配置。
- Skill 明确禁止将 `read_only=true` 字段写入记录。
- 修正累计余额表的默认展示顺序：从插入 `id DESC` 改为“配置日期 `DESC, id DESC`”，最新业务流水显示在顶部。

## Bug 说明

截图中的计算链本身是 `2000 → 4000 → 3700 → 3560`，数值按日期是正确的。问题在于 ID 4 是后插入的 9 月 12 日流水，原默认 `id DESC` 将它放到 9 月 13 日之上，导致正确余额在界面上看似错位。修正后展示顺序为：

```text
2026-09-13  ID 3  余额 3560
2026-09-12  ID 4  余额 3700
2026-09-12  ID 2  余额 4000
2026-09-12  ID 1  余额 2000
```

用户主动点击其他列排序时仍会覆盖默认展示顺序，但余额的计算顺序始终保持“日期 ASC, id ASC”。

## 验收与回滚

本地验收包含 TypeScript、Web 构建、累计余额回归、现有 Viewer/多空间/历史版本回归，以及 CLI/MCP 真实 HTTP 请求参数验证。

本补丁不新增数据库迁移。代码回滚只需切回上一个 release，不需要回退 SQLite Schema。
