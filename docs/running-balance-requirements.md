# 墨问“累计余额”字段 V1 需求文档

## 1. 背景与目标

用户用一张表记录单个账户的收支流水，需要“余额”字段按固定流水顺序自动显示：

```text
本行余额 = 期初余额 + 截至本行的累计收入 - 截至本行的累计支出
```

这与“上一行余额 + 本行收入 - 本行支出”的业务结果一致，但实现上使用累计求和，不把记录串成可断裂的递归依赖链。

V1 的成功标准是：用户在字段面板完成一次结构化配置后，余额列自动出结果，无需写公式、SQL 或手工维护余额。

## 2. V1 范围

### 2.1 包含

- 新字段类型：“累计余额”。
- 单表单账户，每张表最多一个累计余额字段。
- 手动填写一个表级期初余额。
- 选择一个收入字段和一个支出字段；允许其中一个为“无”，但不能同时为“无”。
- 收入/支出只能选择 `number` 或 `currency` 实体字段。
- 选择一个 `date` 或 `datetime` 实体字段作为流水顺序，固定以 `id ASC` 作为同时间的第二排序条件。
- 收入或支出为空时按 `0` 处理。
- 计算结果保留两位小数，以货币样式显示。
- 列表、单条详情、筛选、显示排序、分页、CSV/JSON 导出和 API 查询返回一致的余额。
- 普通 Web/API 写入、AI 助手写入、批量导入、删除、回收站恢复和整表版本恢复后，余额都从原始流水自动重算。

### 2.2 不包含

- 任意文本公式或 Notion/Excel 公式语法。
- 任意“上一行/下一行”字段引用。
- 一张表多账户分组累计、每账户独立期初余额。
- 跨表关联、Rollup、跨记录自定义关系。
- 公式字段引用另一公式字段。
- 计算字段主动回写或修改其他字段。
- 公式配置的历史版本恢复。
- 多币种、汇率、会计科目和财务级精度保证。

## 3. 用户操作

### 3.1 创建

用户在字段面板新增字段：

```text
字段名称：余额
字段类型：累计余额
期初余额：10000.00
收入字段：收入
支出字段：支出
时间字段：交易时间
空值处理：按 0 处理（固定）
精度：2 位小数（固定）
```

保存前显示配置摘要：

```text
余额 = 10000.00 + 累计收入 - 累计支出
计算顺序 = 交易时间升序，同时间按 ID 升序
```

### 3.2 编辑

- 累计余额单元格只读，不进入普通记录编辑表单。
- 修改期初余额、收入/支出字段或排序字段时，弹窗明确说明“整列余额将重新计算”。
- 被累计字段依赖的收入、支出或时间字段可以隐藏，但不能永久删除或改为不兼容类型；接口返回 `409 FORMULA_DEPENDENCY`，并指引用户先修改或删除累计余额字段。

### 3.3 删除

- 删除累计余额字段只删除字段元数据，不修改任何流水数据。
- 符合现有字段隐藏语义时，V1 可先使用隐藏；如提供永久删除，必须二次确认。

## 4. 计算语义

### 4.1 固定顺序

累计顺序只由字段配置决定：

```text
时间字段 ASC, id ASC
```

用户在表格视图中切换排序、分组或筛选，不改变余额计算顺序和结果。

### 4.2 空时间

- 时间字段为空的记录不进入其他记录的累计。
- 该记录的余额显示为空，并在单元格上提示“缺少交易时间，无法计算余额”。

### 4.3 历史流水变更

- 新增最新流水：出现新行余额。
- 修改历史收支：该行及之后的余额自动变化。
- 补录历史流水：按固定时间顺序插入，之后的余额自动变化。
- 删除/恢复历史流水：后续余额自动重算。

### 4.4 版本历史

- 表格历史只保存原始流水行，不将每行计算后的余额重复写入版本 JSON。
- 整表恢复后，按当前的累计余额配置重新计算。
- V1 不恢复历史公式配置；用户修改配置时必须看到影响范围确认。

## 5. API 契约

### 5.1 创建字段

`POST /api/tables/:tableName/fields`

```json
{
  "title": "余额",
  "field_type": "running_balance",
  "formula_config": {
    "version": 1,
    "kind": "running_balance",
    "opening_balance": "10000.00",
    "income_field": "col_income",
    "expense_field": "col_expense",
    "order_field": "col_transaction_time",
    "tie_breaker": "id",
    "null_as_zero": true,
    "precision": 2
  }
}
```

`opening_balance` 使用十进制字符串传输，避免 JSON 浮点在配置层提前丢失精度。`income_field` 或 `expense_field` 可为 `null`。

### 5.2 查询响应

累计余额作为普通读字段返回：

```json
{
  "id": 3,
  "col_income": 0,
  "col_expense": 1200,
  "col_transaction_time": "2026-09-03",
  "field_balance": 10300
}
```

缺少排序时间时，`field_balance` 返回 `null`。

### 5.3 写入行为

- 创建、更新、批量导入的请求如携带累计余额字段，服务端忽略该值，不把客户端结果当作事实。
- API 文档将其标记为 `readOnly: true`。

## 6. 权限与安全

- 创建、修改和删除累计余额字段继承表格写权限。
- 查看计算结果继承表格读权限；不产生跨 Space 或跨表读取。
- 服务端只接受结构化配置和已校验的字段 `column_name`，不接受 SQL 片段、JavaScript 或任意函数。

## 7. 验收标准

1. 期初余额 `10000`，依次记录支出 `500`、收入 `2000`、支出 `1200`，余额依次为 `9500`、`11500`、`10300`。
2. 把第二条的收入修改为 `1500`，第二条及之后的余额正确变化。
3. 补录一条时间最早的支出，其后所有余额自动变化。
4. 改变界面显示排序或筛选条件，同一记录的余额不变。
5. 第二页首条余额承接第一页前面的全部流水，不从期初值重新开始。
6. CSV 和 JSON 导出的余额与 API/UI 一致。
7. 缺少交易时间的记录余额为空，不影响其他记录。
8. 余额单元格和记录编辑器不允许修改计算结果。
9. 被依赖字段可隐藏，但不能被永久删除或改为不兼容类型。
10. 整表版本恢复后，原始流水和重算余额均正确，不把余额重复写入版本快照。

## 8. 性能验收门槛

- 先在开发环境和生产同级 VPS 分别建立无公式基线。
- 10,000 条单账户流水下，暖缓存首页查询 P95 目标不高于 `500 ms`。
- 50,000 条单账户流水下，暖缓存首页查询 P95 目标不高于 `1.5 s`。
- 如达不到门槛，V1 不改为物化余额强行上线；先评估索引、累计检查点或表行数上限，再做发布决策。
